# 长监听 Agent — 问题 / 解决方案 / 踩坑指南

> **用途**：换技术栈重做时带走**知识**。代码不可迁移，以下每条都是「现象 → 根因 → 解法 → 新实现必须满足的约束」。
> **来源**：本项目 v1→v4 实机验证结论（`new_docs/` 设计文档 + 源码）。
> **可信度**：基于设计文档与源码静态阅读整理。本机无 Rust 工具链、无 WSL、Docker 未启动，**所有"测试通过/编译通过"类结论均未实测**。

## 一、12 条核心坑（按"会毁掉系统"的程度排序）

| # | 现象 | 根因 | 解法 | 新实现硬约束 | 出处 |
|---|---|---|---|---|---|
| 1 | 任务执行时 LLM delta 刷屏，麦克风音频堆积、ASR 收不到 → 打断要等旧任务结束，之后永久卡"转录中" | 音频帧走「客户端 → router → 回合 select（低优先级分支）」被 `biased;` 饿死 | 二进制帧**后台任务直连 ASR**，完全绕开回合 select | **高频实时数据通道必须独立于低频高优先级的共享循环** | `ws_v2.rs` L572-584 |
| 2 | 打断/取消旧任务后，旧任务积压的十几句合成本照样播完，新任务语音延误十几秒 | 在收到 `Delta`/`EndOfTurn` 的同一分支里 `for h in pending.drain(..) { h.await }` 顺序排空，期间看不到 `HardStop` | `VecDeque` + 借用队首、每轮只等一句 + `biased;` 控制消息优先；未完成放回队首 | **任何批量/排空 await 必须可被控制消息抢占**（不丢不重） | `tts_pipeline.rs` L281-297 |
| 3 | 打断后旧任务音频"复活"、串味 | `foreground_id`（内容路由）与"声音放行"共用同一字段，更新时机不同 | 两者分离维护；进一步用 **playback token（播放代次）**：每次授权生成新 token，chunk 转发前校验，`is_last` 且匹配才清 | **"是谁"与"哪一次"必须分离**（id + generation/token） | `coordinator.rs` L146-148、L406-416 |
| 4 | LLM 基于过期世界做决策，误取消/误聚焦 | LLM 思考 1~3s 内世界已变 | **乐观并发**：请求带 `decision_id` + `based_on_revision`；返回后用最新快照**逐命令**校验前置条件，拒失效意图、**保留仍合法的意图** | **绝不能"锁住世界等 LLM"**；正确性靠逐命令引用校验（correctness net），不是硬 revision 拒绝 | `compiler.rs` L94-232 |
| 5 | 版本号设计两头堵：全加 control → 决策永远过期；只留一个宽松号 → 新发言/终态被旧决策覆盖 | 把"信息变新"和"合法操作集合改变"混为一谈 | **三维序号**：`event_seq`（漏事件→resync 重建世界）/ `telemetry_seq`（信息变新，不使决策过期）/ `control_revision`（合法决策集合可能改变） | **至少要有"使决策过期"与"不使决策过期"两类序号** | `revision.rs` L40-61、`event.rs` L174 |
| 6 | 任务列表无界膨胀，挤压对当前话语的注意力，漏回显 `decision_id` | 把所有在跑任务塞进 Master 上下文 | `active_tasks` 按 `last_activity_at` 只给最近 **5** 个（数量上限，不是 token 预算） | **面向 LLM 的视图必须有界** | `master_llm.rs` L29 |
| 7 | 并行任务互相串话、串上下文 | 共享可变上下文 | spawn 时拷贝**全局快照**+只追加自己的 local_history；`run_generation` 代次隔离拒绝旧代次迟到事件；记忆三层（DialogueHistory / TaskJournal / LongTermMemory），一个用户 turn 只记一次 | **执行单元间零共享可变上下文**；"谁"与"哪一次执行"分离 | `sub_agent.rs` L94-120、`managers/task.rs` `ensure_generation` |
| 8 | LLM 把"嗯嗯""啊啊啊"当指令执行 | 意图判断交给概率模型 | **确定性噪声过滤兜底**：精确词表 → 全同字符 → 去语气词后 <2 有效字符；边界「嗯等等」必须放行 | **每个概率性判断都要有确定性兜底** | `interrupt_filter.rs` L141-169、L304-314 |
| 9 | TTS 播放时扬声器回放被麦克风拾到，误判"用户在说话" | 无回声抑制 | 播放中 VAD 阈值抬到 0.82 + RMS 门控 0.015 + 200ms 恢复延迟；前端 `onSpeechStart` **本地**先 stop（<100ms 预停） | **预停必须本地完成，不等后端** | `RealtimeVoice.tsx` L27-34、`interrupt_filter.rs` L196-275 |
| 10 | ASR 断线后静默失效；服务端按"音频流空闲"断连 | 依赖通用 ping/pong 心跳 | 指数退避自动重连（1s→30s），重连期间音频缓冲不丢；keepalive 用**真实格式的静音 PCM 帧**（同时喂服务端 VAD） | **长连接必须有业务级心跳** | `seewo_asr.rs` L186-230、L244-279 |
| 11 | 屏幕帧的隐私泄露与 token 成本失控 | 无过滤地上传/注入 | 帧不落盘；pHash(64bit 中值指纹) **AND** 大面积色块变化双条件过滤；5s 节流；攒批 3 帧/5min 一次 LLM 摘要；摘要进 10 分钟滑动窗口；意图门控让纯文字指令零成本 | **多模态输入必须先过滤再上传** | `screen-capture.ts` L1-13/L56-67、`screen_processor.rs` L147-230、`screen_intent.rs` L4-41 |
| 12 | 用户一开口就 cancel，若意图是"排队/继续"则白烧整次 Agent 调用 | 打断 = 取消 | 演进为"独立 LLM 分类器（Interrupt/Suspend/Queue/Continue）"→"Master 统一语义调度"；且**打断只断声音不清任务**（不取消 AgentLoop，任务继续产出文本） | **打断 = 停播报，≠ 取消任务** | `coordinator.rs` L653-672、`03` 文档 §2 |

## 三、重做时的 8 条铁律（从坑反推）

1. **慢决策与快实时必须解耦**：LLM 只产出**声明式计划**，由确定性执行器编译落地。
2. **用户听到的"声音"是单例资源**，需要**授权 token**，不是布尔标志。
3. **"是谁"与"哪一次"分离**（id + generation/token），可推广到请求重试、连接重建、流式订阅。
4. **高频通道独立于低频高优先级循环**。
5. **所有批量 await 必须可抢占**。
6. **面向 LLM 的视图必须有界**。
7. **每个概率性判断都要有确定性兜底**。
8. **打断 = 停播报，不等于取消工作**。

## 四、明确不要重蹈的（架构债）

- `coordinator` **2131 行上帝对象**：WS 传输 / ASR 防抖 / TTS 编排 / 屏幕富化 / 持久化 / 演示回放 / 云上报混在一个文件。重做时按**传输 / 编排 / 领域状态**三层切开。
- **抽象不一致**：TTS 有 `TtsClient` trait，ASR 却是具体类型（`SeewoAsr`/`XfyunAsr`）。新实现里**所有外部依赖（ASR/TTS/LLM/存储）先定义 port**。
- **调度器没有调度**：无优先级、无并发上限、无准入队列、无任务级重试退避（`retryable` 硬编码 `false`）。注意 `ACTIVE_TASK_LIMIT=5` 是**给 Master 的 prompt 截断**，不是并发控制。
- **无度量**：只有 tracing 文本日志，无 metrics、无决策轨迹落盘 → 无法回答"p95 延迟多少"。
- **设计一半的功能留在代码里**（见第五节）。
- **内部接口硬编码、无 feature gate**（渠道/凭据/网关地址与业务代码交织）。

## 六、可正面写进论文的既有结论（有实测支撑）

- Master 决策延迟：**mean 1.9s / p95 2.66s**（v3 决策表 #1）
- 结构化输出（`response_format: json_object`）解析失败率：**0 次**
- 演进叙事：v1 打通"听→懂→执行→说" → v2 打断从规则变意图调度 → v3 单活跃变真并行 → v4 让并行下的决策安全可靠
- 三条主线：**慢 LLM 与快实时的矛盾** / **状态一致性** / **工程判断力（何时用确定性、何时用概率）**
