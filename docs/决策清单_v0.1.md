# 决策清单（v0.1）

> **用途**：把「谁决定了什么」写清楚，避免两类失控：
> ① 待决策项被实现细节悄悄固定下来；② 产品语义被工程师按最省事的方式默认。
>
> **来源**：项目需求规格说明书 §11（13 项待决策）+ 实施计划各里程碑 + M0–M3 开发过程中实际发生的决定。
> **更新规则**：任何一项状态变更都必须同步本表；「已由开发默认」不等于「已确认」。

## 表 2：M0–M3 期间**未请示即做出**的决定

这张表的目的是让这些决定可被逐条否决。它们全都不是"实现细节"，而是有产品后果的选择。

| 决定 | 我当时给的理由 | 可逆性 |
|---|---|---|
| 用 Node 原生类型剥离跑 TypeScript（不引入 tsx/ts-node） | 少一层依赖；代价是受 `erasableSyntaxOnly` 约束（禁 enum / 参数属性 / 装饰器） | 易（改回 tsx 只需加依赖 + 去掉约束） |
| 包管理器用 npm（本机无 pnpm）；测试用 vitest | 工具链可用性 | 易 |
| 把 4 份既有文档移入 `docs/` | 对齐实施计划 §5 的目录建议 | 易（`git mv` 回来即可） |
| **并发上限默认 4** | 计划要求"配置化、不沿用旧项目数值"，我选了一个中性值 | 易（改配置） |
| **准入策略为 FIFO，不做优先级/饥饿防护** | 最小复杂度，计划把优先级列为待决策 | 中（要改 Scheduler 内核） |
| **ADR-002 把 M3 的候选状态机冻结为规范** | SRS §4.1 写明是「候选状态，待 PoC 验证」，我用穷举测试把它固化了 | **中** —— 现在改成本最低（24 项测试） |
| 自定义端点 provider 命名为 `cf-fan`，`api: "openai-responses"` | 依你提供的"协议：openai response"推断 | 易 |
| 不做 generation 前进的生产路径（重试/恢复） | 计划明确"首版不实现任务级重试" | 中（M7） |
| 不做取消超时看门狗；Worker 端口无超时信号 | 计划把 watchdog 放在 M7 | 中（M7） |
| Git 提交身份用 `jarvis-dev` | 本机全局 git 身份不可读 | 易 |

## 表 3：M4 动手前**必须**表态的项

**状态：已于 2026-10-10 全部表态完毕**，结论见 ADR-003。

| 项 | 结论 |
|---|---|
| **A. revision 维度** | ✅ **两维**：`eventSeq`（事件完整性，不使决策过期）+ `controlRevision`（合法决策集合变化时才递增） |
| **B. Master 结构化输出通道** | ✅ **提示词要求 JSON + 严格解析与降级**，不依赖 provider 的 `response_format`；已在真实模型上验证可行 |
| **C. 结果优先级字段** | ✅ **现在就加优先级枚举**（`low`/`normal`/`high`/`urgent`），**不启用抢占**；抢占条件留到 M5 |
| **D. 准入策略** | ✅ **接受 FIFO + 默认上限 4，到 M8 再定**（用调度延迟基线决定是否需要优先级） |
