## A. 基础链路（最重要，先跑通这个再看其他）

### A1 文本输入 → Master 决策 → 任务执行

**操作**：在左侧输入框输入一个**任务型**请求，例如：

```
请读取 src 目录下所有 TypeScript 文件，逐个说明它们的职责，并输出一份详细报告
```

**预期**：
1. 界面短暂显示「Master 决策中…（真实模型调用，通常 2–4s）」
2. 出现决策结果，任务卡片出现并进入 `running`
3. 任务卡片里出现**「🔄 正在生成…」实时文字**（逐字增长）
4. 任务完成后卡片显示完整结果（Markdown）+ 可展开的「🔊 播报稿」

**观察点**：
- 实时文字在**工具调用期间会暂停**（模型没在产出文本），输入完最终答案后会继续——这是正常的
- 中间过程的文字可能是**英文**（Pi SDK 系统提示词是英文过的），最终结果与播报稿是中文

**失败时的信息**：把页面顶部的**红色错误横幅文字**发我（如果有），以及 `npm run demo` 终端里的日志尾部。

### A2 并发（多任务并行）

**操作**：发一个复合请求：

```
同时做两件事：统计 src 目录下 TypeScript 文件数量；并列出 tests 目录下的测试文件数量
```

**预期**：Master 建议**两个独立任务**，两个任务卡片同时在 `running`（并发上限 4）。

> 注意：Master 有时会把这类请求判成**一个**任务（它认为不该拆）。这是模型行为波动，不是缺陷。想要两个任务，措辞上强调"两件独立的事"。

### A3 取消隔离

**操作**：在两个任务都在跑时，输入：

```
取消统计文件数量那个任务
```

**预期**：只有目标任务进入取消流程，另一个**不受影响**继续执行。
时间线会显示取消过程（请求发出 → 停止确认 → 状态提交）。

## B. 语音输出（TTS 播报）

> 前置：`.env` 里 `JARVIS_VOICE_ENABLED=1`，且 `DASHSCOPE_*` 配置完整。

### B1 结果播报

**操作**：发一个短任务（例如「用一句话说明 1 加 1 等于几」）。

**预期**：任务完成后**真的听到语音**念出播报稿（不是面板上的完整 Markdown）。

**观察点**：面板右侧「音频来源」应显示**「真实 TTS（阿里云百炼）」**；若是「模拟分片」说明语音没启用成功。

### B2 停播（本地预停）

**操作**：在正在播报时，点 **「模拟用户开口 → 停播」**。

**预期**：
- 声音**立刻**停（本地预停，不等后端）
- 时间线出现停播事件；音频「已停播」代次被作废
- 之后**旧音频不会复活**

### B3 用户讲话时让路

**操作**：点 **「模拟用户正在讲话」** → 再发一个任务 → 等结果出来。

**预期**：
- 结果显示在面板上（**面板照常更新**）
- **不播报**（时间线显示「语音交付暂缓」）
- 点「模拟用户停止讲话」后，暂缓的结果**自动恢复播报**

## C. 语音输入（ASR + 麦克风）

### C1 实时转写

**操作**：点 **「🎤 开始说话」** → 浏览器请求麦克风权限（允许）→ 说一句话，例如
「帮我看看 src 目录下有多少个 TypeScript 文件」→ 点 **「⏹ 结束说话」**。

**预期**：
1. 说话过程中，绿色框里出现**灰色斜体的中间结果**（会不断变化、可能不完整）
2. 结束后出现**绿色的终稿**（完整、补全标点）
3. **终稿自动进入调度链路** → 创建任务并执行

**观察点**：中间结果与终稿的差异是正常的（中间结果会截断、大小写未定）。这正是系统不把中间结果当最终结果的原因。

### C2 说话时播报自动让路

**操作**：在正在播报时开口说话。

**预期**：检测到语音活动 → 播报让路（不需要手动点按钮）。

**失败时的信息**：页面红色横幅文字 + 浏览器控制台（F12）里的报错。

## D. 屏幕观察（M6d）

> 前置：**默认关闭**，必须手动开启。开启后摘要会把一张约 35KB 的截图发给模型 API。

### D1 开关与默认状态

**操作**：看右侧「👁 开启屏幕观察」按钮。

**预期**：按钮**可点**（不是灰的）；状态显示「屏幕观察：已关闭」。

### D2 采集与摘要

**操作**：
1. 点「👁 开启屏幕观察」
2. **真实地改变屏幕内容**：切换窗口、滚动页面、开关一个应用
3. 等 15–30 秒

**预期**：
- 时间线出现 `screen_changed`（屏幕发生有意义变化）
- 攒够 3 帧后出现 `screen_batch` 与 `screen_summary`
- 面板上显示**模型摘要**（描述你屏幕上正在做什么）

> ⚠️ **关键**：如果屏幕**完全不动**，双条件是正确拒绝的（不会产生摘要、也不调模型）。
> 这是设计行为——避免对静止画面白花成本。**必须真的改变屏幕内容**才能看到摘要。

### D3 意图门控（纯文字指令零成本）

**操作**：发一条**纯文字**请求（例如「写一个二分查找函数」）→ 看时间线里的 `screen_gate`。

**预期**：显示
`纯文字指令：不注入屏幕上下文（零 token 成本）`

### D4 意图门控（提及屏幕时注入）

**操作**：先确保窗口里有摘要（做 D2）→ 发「**屏幕上现在显示的是什么**」。

**预期**：时间线 `screen_gate` 显示
`注入 N 条屏幕摘要（命中屏幕指代词：屏幕）`

### D5 关闭即不留残余

**操作**：点「⏹ 关闭屏幕观察」。

**预期**：时间线显示「屏幕观察已关闭（未满批的帧已丢弃）」。

## E. 持久化与重启恢复（M7）

### E1 历史可查询

**操作**：
```powershell
Invoke-RestMethod 'http://127.0.0.1:7717/api/history?limit=10' | ConvertTo-Json -Depth 4
```

**预期**：能看到刚跑过的任务，含 `state`、`resultSummary`、`spokenSummary`。

数据落在 **`.data/jarvis.db`**（已被 gitignore，含你的对话与屏幕摘要，**不会入库**）。

### E2 重启后的未知状态被标记（核心验收）

**操作**：
1. 发一个**长任务**（例如「读取 src 目录下所有文件，逐个详细分析职责」）
2. 确认任务卡片是 `running`
3. **在终端按 Ctrl+C 杀掉服务**（模拟崩溃）
4. 重新 `npm run demo`
5. 启动日志里应出现 `runtime.recovery_unknown_tasks`，并带 `"note":"已标记为结果未知，未自动重跑"`

**预期**：
```powershell
Invoke-RestMethod 'http://127.0.0.1:7717/api/recovery' | ConvertTo-Json -Depth 4
```
- `markedUnknown` ≥ 1
- `pending` 里列出那些任务（这才是"待核对"）

**同时验证**：历史任务总数**没有增加**（没有自动重跑），那个任务的状态**仍是 running**（没有被谎报成 succeeded / failed）。

### E3 显式重跑

**操作**：
```powershell
$body = [System.Text.Encoding]::UTF8.GetBytes('{"taskId":"task-2"}')
Invoke-RestMethod 'http://127.0.0.1:7717/api/recovery/replay' -Method Post -Body $body -ContentType 'application/json'
```

**预期**：返回 `status: replayed` 和一个**新的** `newTaskId`（例如 `task-3`）。

**关键**：
- 新任务 id **不能**和任何历史 id 相同（`task-1`/`task-2` 已被占用）
- 老任务仍保留「结果未知」标记 + `replayTaskId` 指向新任务

### E4 重复重跑被拒绝

**操作**：对同一个 taskId 再调一次 E3。

**预期**：返回 **HTTP 409**，说明"已经重跑过"。

**另外**：对**已完成**的任务调用重跑，也应被 409 拒绝（它不是"未知"状态）。

## F. 预期会失败 / 未实现的（**不要当成 bug**）

| 项 | 现状 |
|---|---|
| 任务开始后要**等任务做完才出声** | ⚠️ 已知缺陷（首声延迟 ≈ 任务时长 + 1.2s 窗口）。**优化方案已提出但按你的指示未实施** |
| Worker 按需截图工具 | 未实现（按你的指示留空） |
| 面板显示重启核对 UI | 未实现（用 `/api/recovery` 接口） |
| 优先级参与排队/抢占 | 未实现（FIFO，已确认延到 M8） |
| 跨重启幂等去重 | 未实现：`TaskRecord` 不携带幂等键，重启后同一决策再提交**可能创建重复任务** |
| 屏幕摘要在静止画面上不会产生 | **设计行为**，不是 bug |
| 同一句请求有时判成一个任务、有时两个 | 模型行为波动，不是缺陷 |
| 中间过程文字是英文 | Pi SDK 系统提示词是英文的；最终结果是中文 |
| 演示中出现 Worker 自己写文件到仓库 | 决策 #8（工具安全边界）**已显式延后**，风险仍在 |
| `node:sqlite` 实验性警告 | stderr 会打印 `ExperimentalWarning`；PowerShell 可能把它显示成错误，但**测试退出码是 0** |
